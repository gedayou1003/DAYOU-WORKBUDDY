## 一、本轮已修（含变异自证）

### 1. `fetch_zsxq.py` —— `--window` 静默失效【最值得修的一项】

窗口参数是本项目唯一的抓取范围控制，也是**事故高发点**。旧实现有两处静默回退：

| 输入 | 旧行为 | 后果 |
|---|---|---|
| `--window nooon`（拼错） | 三个 `if` 全不匹配 → 落回默认 `morning` | 窗口无声变成「前一天 16:00 起」 |
| `--window`（后面没值） | `IndexError` 被 `except: pass` 吞掉 → 同上 | 同上，且**零提示** |

**这与 2026-09-21 晨报「漏掉整个周末」是同一族机制**：当时是没传 `--window`，若传了但拼错，结果完全一样且同样无任何提示。

修法：白名单校验，非法取值一律 `stderr` + 退出码 1；`morning` 改为显式分支，让"走到默认分支"只可能是"确实没传"。

### 2. `get_daily_ohlc.py` —— 整型入参静默回退默认值

| 输入 | 旧行为 | 后果 |
|---|---|---|
| `000001 abc` | `except ValueError: pass` → days=1 | 以为取了 N 天，实际只有 1 天 |
| `--ttl abc` / `--ttl=` | 静默 → 用 `DEFAULT_TTL_MIN`=30 | 以为设了 TTL，实际是默认值 |
| `--no-cach`（拼错） | 被静默吞掉 / 当成位置参数 | 以为禁用缓存，实际仍在读缓存 → **拿到陈旧价格** |

修法：新增 `_int_arg()` / `_need_val()`，非法入参 `raise ValueError` → `__main__` 转成 `[FAIL] 参数错误：…` + 用法 + 退出码 1；未知选项显式报错。

### 4. `test_layout_typography.py` —— 日期相关断言「测试自坏」，已红 2 天无人发现【本轮最有价值的发现】

跑全量测试时发现该测试 **FAIL 2 项**，而它已经失败了两天。

**故障机理（测试自己会随时间腐烂）**：

| 环节 | 内容 |
|---|---|
| 断言 | 「since 未到 → 同样 7 次不应判红，但要打 INFO 说明豁免」 |
| 原实现 | 报告日期写的是 `TODAY`（= `datetime.date.today()`） |
| 写测试时 | 2026-09-18 <`SINCE`=2026-09-19 → 前提成立，测试通过 |
| 2026-09-19 起 | 日历越过 `SINCE` → **前提永久失效**，断言从「豁免正确」翻转成「规则该响却没响」 |
| 结果 | 测试连红两天，**无人发现** |

**第一次修复尝试（错误的）**：把 `TODAY` 换成 `D_BEFORE`（= `SINCE` 前一天）。结果仍然红 1 项——因为 `check_layout.py:191` 有一道 `_is_today_report()` **早退闸门**：只对当日报告做全篇计数，报告日期一旦不是今天，整节直接 `return`，**连豁免 INFO 都不会打**。

于是暴露出一个更深的事实：**「报告日期 < since」与「报告是今天的」这两个条件，在日历越过 `SINCE` 之后变成互斥** —— 也就是说「since 未到」这条豁免路径**已经无法用真实日期覆盖**了。

**最终修复**：报告日期仍用 `TODAY`（通过 `_is_today_report` 闸门），新增 `pending_since()` 上下文管理器把**规则起点临时推到明天**，从而构造出「规则尚未生效」的场景。断言与日历彻底解耦。

```
[OK] since 未到（起点 2026-09-22 晚于报告 2026-09-21）时，同样 7 次不判红（实测 0 条）
[OK] 但打 INFO 明示「60F 中轨 阈值自 2026-09-19 起生效，本报告不参与」
RESULT: ALL PASS
```

**结构性原因**：项目此前**没有聚合测试入口**，12 个测试只能一个个手动跑 —— 单点测试红了没人知道。这是「红了 2 天」真正的根因，比那两行断言重要得多。

**已落地**：新增常驻 `run_tests.py`（跑全部 `test_*.py`，逐项 rc + 耗时，单测 300s 超时保护，失败时提示「先看该测试是否依赖『今天』」）。

> **铁律**：**没有聚合入口的测试体系 ≈ 没有测试体系。**单点测试会随日历、环境、数据静默腐烂，而腐烂的测试比没有测试更危险——它会让人以为有保护。

## 二、待处理问题（按优先级）

### P1 `forecast_analyze.py:38` `run_py()` 不看 returncode【影响面已收窄，如实说明】

`run_py()` 直接 `return r.stdout.strip()`，不检查 `returncode`。听起来危险，但**逐条核实后影响面比预想小**：

- 唯一调用方是 `fetch_ohlc()` → `get_daily_ohlc.py`
- `get_daily_ohlc.py` 出错时**会把错误写成 JSON 打到 stdout 再退 1**（如 `{"error": "无法识别的标的"}`）
- 上层 `json.loads(out)` 因此仍能拿到可用的 error 字典

**真实缺口只有一种**：子脚本**崩溃**（traceback）导致 stdout 为空 → 上层得到 `{"error": ""}`，`stderr` 里的真实原因被丢掉。

建议修法（不改变现有成功/业务失败路径语义）：

```python
r = subprocess.run([PY, script] + list(args), capture_output=True, text=True, encoding='utf-8')
out = (r.stdout or '').strip()
if not out:                       # 只在「无 stdout 可解析」时升级
    raise RuntimeError('%s 退出码 %d 且无 stdout：%s'
                       % (os.path.basename(script), r.returncode, (r.stderr or '').strip()[-300:]))
return out
```

## 五、新发现的技术陷阱（建议沉淀进 MEMORY）

### 1. `git ls-files` 输出中文路径会被 `core.quotepath` 转义成八进制

实测：`git ls-files .workbuddy/` 返回的 `模型体检报告_2026-09-16.html` 是 `".workbuddy/\346\250\241\344\275\223..."` 这种形式，导致我用简单子串比对时**误判它为「未跟踪」**（实际已入 index）。加 `-c core.quotepath=false` 后立刻正常。

> 凡做「文件是否被 git 跟踪」的比对，一律加 `-c core.quotepath=false`；含中文名的项目必踩。
> 与本机既有的 `git check-ignore --stdin` 读不到标准输入属**同源问题**：git 在 shim/编码环境下的输入输出约定不可想当然。

### 2. 变异测试用「非贪婪正则」会只替换一半 → 变异不生效

`fetch_zsxq` 的守卫块里有**两个** `sys.exit(1)`（缺值 / 未知取值）。`(?:.*\n)*?` 只吞掉第一个，第二个仍在拦非法入参，于是变异体 rc 仍为 1，表面上像「修复无效」，实际是变异本身没做对。

> 改用**标记切片**（`s.index(头标记)` / `s.index(尾标记)`）替换整块，并加断言：变异后守卫字样必须消失。
> **推论：变异测试自己也要有断言**，否则它给出的红/绿都不可信。

### 3. 测试里的「今天」会随时间变成永久失效的前提

见第一部分第 4 项。凡断言依赖「当前日期与某个阈值的关系」，一律要问：**日历越过阈值之后，这个断言还成立吗？** 若不成立，要么显式构造（如把规则起点移到未来），要么用常量日期 + 绕过早退闸门。

### 4. 早退闸门会静默吃掉「豁免 INFO」

`check_layout.py` 的 `_is_today_report()` 会让非当日报告整节 return。这本身是合理设计（历史报告不该被新尺子量），但它的副作用是：**任何"用旧日期构造场景"的测试都会静默测不到东西**（返回空结果 → `not w` 通过 → 看起来像"豁免正确"）。测试里必须显式断言「应该有东西」（如 INFO 存在），否则空结果会伪装成通过。

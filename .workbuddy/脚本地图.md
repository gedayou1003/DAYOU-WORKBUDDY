| 脚本 | 职责 |
|------|------|
| `chain_apply.py` | **链操作统一入口**：一条命令完成「复盘上一条 + 追加本期」跨 forecast/consensus 两条链，含**机器回读断言**（写盘后重读校验 status，不符即非零退出）。用法见《报告生成流程.md》 |
| `chainlib.py` | 链操作公共库：load/save、幂等 upsert、回读断言、**程序化偏差统计**（`bias_stats()` 精确复现报告中的四维数字）。可直接跑自检 |
| `calc_tech.py` | 技术指标（日线/60F/15F 的 MACD(12,26,9) + MA55/MA20 + 近 10 日前低），`--code` 参数化 |

> `chain_apply.py` 的三条硬保证：**① 幂等**（review 存在 / record.id 存在则跳过，绝不重复写）；
> **② 机器回读断言**（根治 9/15「脚本 stdout 说写了、链其实没落盘」事故，替代人工回读纪律）；
> **③ pending 守卫**（写完 pending > 1 条即提示可能漏复盘）。支持 `--dry-run` 与 `--bias-only`。

## 〇·补、2026-09-16 巡检修复（大修落地后的回归体检）

大修落地后通跑一遍，发现并修复 3 个真问题（**均为新链路自身缺陷**，旧脚本时代不存在）：

| 编号 | 问题（已实测复现） | 修复 |
|---|---|---|
| **J-1** | **空壳 review 无门槛**：`--init-template` 产出的空壳 review 被直接接受 → 上一条 pending 被误标 verified（四维 verdict 全空、`actual.close=0`），**机器回读断言还报绿**（它只校验 status）；又因幂等规则「已有 review 不覆盖」而**永久无法修正**，只能手改 JSON | `chainlib.review_is_blank()` + `apply_review(strict=True)` + `upsert_pending` 占位符校验；`chain_apply` 收集被拒项并**退出码 2** |
| **J-2** | **cp936 控制台崩溃**：`chainlib.py` 自检与 `chain_apply.py --bias-only` 在 Windows cmd 下 `UnicodeEncodeError: '\u2705'` 直接退出 —— 而这正是收盘档要用的命令 | 模块级 `sys.stdout.reconfigure(errors='replace')` + `sym()` 符号降级 + `render_bias_table(ascii_safe)` 自动切 `[O]/[~]/[X]`（报告文件仍写完整 emoji） |
| **J-3** | **模板占位符未替换**：`--init-template` 的 `validate_prev` / `review.id` 留 `YYYY-MM-DD-<tier>` 字面量，而 `record.id` 已填真实日期，二者不一致极易忘改 | 自动预填为「该链最后一条 id」；未填字段改用 `<<< 必填` 哨兵（哨兵同时被空壳校验判定为「未填」，双保险） |

> 手动喊「跑晨报 / 午间 / 收盘」时的流程速查。定时任务已废弃，本文件只记「怎么跑」。
> 运行约定：`$PY` = `~/.workbuddy/binaries/python/envs/default/Scripts/python.exe`（换机后 `~` 自动展开，勿写死 C:\Users\gedayou）；cwd 已是工作区根，脚本用相对路径 `.workbuddy/xxx.py`。

## 执行约定（固定动作 · 每次跑都照做）

> 目的：省 token、省时间。这两条是**行为层零成本优化**，不用改任何脚本，跑报告时直接照做即可。

1. **图片不逐张 Read**：抓取脚本已提取每张图的文字，只对**关键图**用 Read 看细节（大鹏鸟盘前热榜、T&J 截图，约 5-10 张），其余图片一律用脚本文字。逐张 Read 是 token 大头，砍掉能省 70%+ 图片消耗。
2. **引擎/抓取受控并发**：所有后台任务（引擎 A/B/C、四周期联动、星球抓取、行业榜）**每批并发 ≤2**，跑完一批再起下一批。超过 2 个并发会触发沙箱拦截（已踩过坑：一次并发 5 个失败 3 个），失败时改为串行重跑即可。
3. **去重（信息原子唯一落地）**：五块是递进推导链，同一个信息原子（主线/关键位/反转信号）全篇只完整落地一次，下游用指针。① 存素材 ② 存判断 ③ 存结构 ④ 存结论，各层只产出自己的增量。详细对照表见 `报告逻辑排版完整性规范_v2.md·二·去重原则`，量化红线见同文件 **3.8 篇幅与粒度控制**。
4. **链操作走统一入口**（2026-09-16 起）：不再每日新建脚本，改用
   ```
   $PY .workbuddy/chain_apply.py --payload .workbuddy/payload_<日期>_<档位>.json
   ```
   一条命令完成「复盘上一条 + 追加本期」跨 forecast / consensus 两条链，并自动做**回读断言**（写盘后从磁盘重读校验 status，不符即非零退出）。详见下节。

## 链操作统一入口（2026-09-16 替换 42 个每日脚本）

原先每期都要「复制上一份脚本 → 改 8-10 个日期 → 改判定文本」，累积出 42 个同构脚本（~304KB）＋ 3 个复盘脚本。现已合并为 **1 个入口 + 1 份 JSON**：

```
$PY .workbuddy/chain_apply.py --init-template morning 2026-09-17   # 生成空白 payload 骨架
# 填好 payload 后：
$PY .workbuddy/chain_apply.py --payload .workbuddy/payload_2026-09-17_morning.json
$PY .workbuddy/chain_apply.py --payload <同上> --dry-run            # 预演，不落盘
$PY .workbuddy/chain_apply.py --bias-only                           # 只打印偏差统计表
```

payload 三段（均可选）：`forecast{validate_prev, review, record}` / `consensus{同上}` / `bias{print, write}`

**内置保证**：
- **幂等** —— review 已存在 / record.id 已存在则跳过，绝不重复写
- **机器回读断言** —— 写盘后重新从磁盘读回校验 status，不符直接非零退出（**替代原先「跑完记得回读 chain」的人工纪律**，即 9/15 漏落盘事故的根治）
- **空壳校验**（2026-09-16 巡检新增）—— review 四维判定全空、或 record 的 direction/range/confidence 残留 `<<<` 占位符 → **拒绝写入并退出码 2**。防止「模板忘填就直接跑」把上一条 pending 误标 verified（那种污染因幂等规则无法回滚，只能手改 JSON）
- **pending 守卫** —— 写完若 pending > 1 条即提示「可能漏复盘上一条」
- 兼容 chain 的 list / dict 两种结构

**退出码**：`0` 正常 · `1` 参数/文件问题 · `2` 校验未过或有记录未落盘（**必须处理，不能当成功放过**）。

`--init-template` 会自动预填 `validate_prev` / `review.id` 为「该链最后一条 id」，未填字段一律写成 `<<< 必填` 哨兵；把这些哨兵留在 JSON 里直接提交会被拒绝（退出码 2）。

辅助脚本：
- `$PY .workbuddy/chainlib.py` —— 自检：打印两条链状态 + 偏差统计（cp936 控制台会自动降级符号，不会崩）
- `$PY .workbuddy/test_chain_apply.py` —— **回归测试**：6 组用例（空壳×2 / 正常填写 / 占位符 record / 幂等 / 真链条数），全程在 `_test_sandbox` 沙箱内跑、不碰真链；**改动 chainlib 或 chain_apply 后必跑**
- `$PY .workbuddy/calc_tech.py [--code 000001]` —— 技术指标（日线/60F/15F 的 MACD+MA55/MA20+近10日前低），取代每日复制的 `calc_tech_MMDD.py`
- `$PY .workbuddy/digest_zsxq.py` —— 星球抓取摘要，取代 `digest_MMDD.py`

> 旧的每日脚本已全部移入 `.workbuddy/archive/daily_scripts/`（44 个），仅供回溯，日常不再使用。

## OHLC 取数缓存（2026-09-16 新增，解决报告内数值自相矛盾）

`get_daily_ohlc.py` 按「日期 + 槽位」落盘缓存，**默认 TTL 30 分钟**：

```
$PY .workbuddy/get_daily_ohlc.py 000001 1 --slot close     # 推荐：报告流程按档位传槽位
$PY .workbuddy/get_daily_ohlc.py 000001 --force            # 强制刷新
$PY .workbuddy/get_daily_ohlc.py 000001 --no-cache         # 完全禁用缓存
```

- 一份报告生成过程通常 < 30 分钟 → **报告内所有取数完全一致**
- 各档位相隔数小时 → TTL 必然过期 → 自动重取，**午间档快照不会污染收盘档真实收盘价**
- 起因：原先无缓存，一份报告被反复调用 4-5 次；实测 9/16 相隔 1 分钟两次调用拿到 close **3855.48(-0.23%)** vs **3854.20(-0.26%)**，同报告印出两组现价

## 预判与复盘（详见 `预判规则_v5.md`）

1. 读 `forecast_chain.json` 找上一条 `status="pending"` → `get_daily_ohlc.py` 取实际 OHLC → 方向/区间/支撑/压力四维判定 ✅/⚠️/❌ → `verified` 写 review
2. 按 v5 规则（方向量化打分 + 方向不明 + 55线支撑压力）形成本期预判 → 追加 `pending`
3. 偏差统计：四维配对计数（各自 ✅命中/⚠️部分/❌失效，不抵消）+ `bias_type` 三分类；某类 ≥3 次仅标「规律已现」，**绝不修改策略/参数**

## 共识复盘（`consensus_chain.json`）

读 pending → 逐条 ✅兑现/❌未兑现/⏳跟踪中（短期用走势验证、中期标跟踪、事件事实类不参与）→ `verified` 写 review → 本期共识追加 `pending`

## 抓取要点

- 主抓取 `fetch_zsxq.py`（双通道：zsxq-cli + Cookie 直连，已内置分页+图片下载+附件元数据）
- **Cookie 失效（HTTP 401/403）为 fail-fast**（2026-09-16 改）：立即终止该星球并**只提示一次**，不再重试 3 次（原先 4 星球 × 3 次 = 每期 12 次必然失败的请求，连续 4 期白跑 48 次）。仅 5xx / 超时保留重试。日志出现 `COOKIE_AUTH_FAILED=n` 即需更新 `.workbuddy/zsxq_cookie.txt`，不中断流程
- **图片正文**：优先用抓取脚本已提取的文字，仅关键图（大鹏鸟盘前热榜、T&J 截图）用 Read 看细节，其余不逐张 Read（省 token）
- T&J 话题原文一字不差归档 `outputs/TRUTH_AND_JUSTICE_原始记录_YYYY-MM-DD.md`（仅晨报做）

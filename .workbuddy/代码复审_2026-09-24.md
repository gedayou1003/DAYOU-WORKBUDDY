## 一、复审发现（按严重度）

### 🔴 R1 · `gen_forecast_svg.py` 的覆盖守卫「装了但装错了位置」——事故其实**已经发生且不可恢复**

**这是本轮最重要的一条，而且推翻了我上一轮的说法。**

**事实核对（决定性证据）**：

```
outputs/000001_forecast_2026-09-23.svg  md5 = 445af25900f869655f610dbc1d8923ec
outputs/000001_forecast_2026-09-24.svg  md5 = 445af25900f869655f610dbc1d8923ec
                                        ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ 完全相同
```

两张图**字节级一致**。而 9/23 午间档的图应该是「现价 3936.52? → 由 9/22 收盘 3952.13 推出的预判」，
9/24 晨报的图才是「现价 3936.52」。两者 md5 相同只有一个解释：
**9/23 那张已被 9/24 的内容覆盖，且没有备份、无从恢复。**

**我上一轮的说法为什么是错的**：

| 上一轮我说的 | 实际 |
|---|---|
| 「已显式 `--out` 重生成到正确路径」 | ✅ 真的做了 |
| 「已给脚本加守卫，防同类覆盖再次发生」 | ⚠️ **守卫只加在 `else`（默认路径）分支里** |

而这次覆盖是**通过显式 `--out` 打进去的** ——
`--out "outputs/000001_forecast_2026-09-24.svg"` 时脚本走 `if a.out:` 分支，
**`date` 与 `id` 的一致性校验根本不执行**。
所以：**我加的守卫，恰好覆盖不到我自己制造的那次事故的路径。**
真实风险从来不是「默认路径按 date 命名」，而是「**写一个已存在的、别的档位的图**」——
**这与路径怎么来的无关**。

**已修**（本次）：

在**按输出路径本身**判定的位置新增守卫（对 `--out` 与默认两条路径一视同仁）：
- 目标文件已存在、且文件名中**不含本记录 id 的日期** → **拒绝覆盖并退出 1**
- 同日重跑自己的图 → 放行（正常）
- 需刻意重绘历史档 → `--force` 显式越过

**实测（真实链路，不是沙箱）**：
```
gen_forecast_svg.py --pred 2026-09-24-morning --out .../000001_forecast_2026-09-24.svg  → rc=0 ✅ 放行
gen_forecast_svg.py --pred 2026-09-24-morning --out .../000001_forecast_2026-09-23.svg  → rc=1 ✅ 拒绝
```
拒绝时的报错文本已点明「覆盖」「别的档位」「md5 相同、不可恢复」「--force 逃生」。

**回归测试**：`test_svg_date_mismatch.py` 由 4 组扩到 **6 组**（新增「--out 覆盖别的档位必须拒」
「同日重跑必须放行」「--force 必须放行」「目标不存在必须放行」），**10 条断言 ALL PASS**。

> **教训（比这条 BUG 本身更值钱）**：
> **「加了校验」≠「校验覆盖了出事的路径」。** 加守卫时必须以**事故的实际形态**去验证它，
> 而不是以**自己设想的形态**。我上一轮设想的是「手滑没给 --out」，真实事故是「显式 --out」——
> 两者路径不同，守卫就擦肩而过了。
> 同类：**守卫的正确判据是「我要写的这个目标安全吗」，不是「我这个参数合理吗」。**

### 🟠 R2 · `smoke_pipeline.py` 的「0 受保护文件被改」是**弱证据**，且存在真实盲区

冒烟报告 `受保护文件被改 0 · 新增文件 2`，看着很干净。但：

**盲区 1 — 同名同大小覆盖看不见（已确认被利用过）**
R1 那次覆盖后新旧同为 7738 字节。若 `outputs/*.svg` 当时不在 `PROTECTED_GLOBS` 里，
冒烟不会报；**即使报了，只要内容恰好一致也会漏**。
不过更关键的是下面的盲区 2——

**盲区 2 — 「受保护」只保证「跑冒烟时没变」，不保证「内容是对的」**
`PROTECTED_GLOBS` 是**跑前取快照、跑后比对**。
R1 的污染发生在**跑冒烟之前**（08:47 覆盖 → 09:19 才跑冒烟）。
于是冒烟看到的是「一份本来就已被污染的图」，前后一致 → **报 0 改动**。
**它是「这段时间没被动过」的证明，不是「内容正确」的证明。** 这两件事经常被混为一谈。

**盲区 3 — `outputs/*.svg` 的内容从来没有被任何校验器检查过**
`check_layout.py` 只查 `.md`；`check_integrity.py` 查链与报告产物**存在性**（不查 SVG 内容）；
`check_display_name.py` 查脱敏。
**即：SVG 里画的是哪一天的预判、关键位对不对，全链路无人校验。**
R1 这种「图被换成别档位的」在机器上完全静默。

**建议**（未擅自实施，属设计变更）：

1. **SVG 加一条最低限度的内容自检**：`<title>` 或 `<desc>` 里写死
   `pred=<记录id> / date=<目标日>`，由 `check_integrity.py` 校验
   「文件名里的日期 == SVG 内自述的目标日」。成本极低，正好堵住 R1 这类。
2. 冒烟增加**弱于 md5 的语义核对**：不只比 hash，也核对「每个受保护交付物能否推出所属档位/日期」。
3. ⚠️ **不要**把「冒烟 0 改动」当作「产物正确」的证据写进任何结论 —— 语义上它只说「这段时间没动」。

### 🟡 R4 · `gen_forecast_svg.py` 取 `actual` 的逻辑对「跨档位同日」不敏感（潜在，未触发）

```python
act = None
for r in reversed([x for x in chain
                   if x.get('status') == 'verified' and isinstance(x.get('review'), dict)]):
    a = r['review'].get('actual')
    if isinstance(a, dict) and all(k in a for k in ['open','high','low','close']):

        break
```

它取的是「**链上最后一条**带完整 OHLC 的 verified 记录」，而不是「与本次预判 target 匹配的那条」。
本轮无害：`2026-09-24-morning` 前面正好是 `2026-09-23-noon`（actual=9/23），语义正确。

**但**：`2026-09-18-close`（target=9/21）与 `2026-09-21-morning`（target=9/21）**target 相同**，
若将来出现「中间夹一条 target 不同的记录」，这张图的「真实走势」就会叠错那一天 ——
**图照样画出来、照样不报错**，与 R1 同一族（静默的错误数据）。

**建议**：改为按 `target` 匹配（记录 id 日期 ≤ target，取最接近且早于等于 target 的那条 actual），
且在 `SVG written` 里把实际用到的 `actual.date` 打出来（现在就打了 `now` 但没打 actual 的日期）。

### R2-1 · SVG 自述身份 + 校验器核对 ✅

**生成端** `gen_forecast_svg.py`：SVG 头部写入

**校验端** `check_integrity.py` 新增 **【8】走势图自述一致性**：
`000001_forecast_<日期>.svg` 的文件名日期必须 == `<desc>` 里的 `date=`；
不一致 → ERROR；无 `<desc>` → 亦 ERROR（旧图未自述，重跑生成器即可补上）；
`SVG_DESC_SINCE = '2026-09-25'` 之前的图归历史例外（当前 22 张）。

```

❌ 存在 ERROR：必须处理            EXIT=1
```

### 本轮追加沉淀的三条铁律（已写入 `.workbuddy/memory/MEMORY.md` §40）

1. **加守卫必须以「事故的实际形态」验证**，不是以「自己设想的形态」——
   否则会得到「守卫装好了、但装的不是出事的门」这种最危险的假安全感。
2. **守卫的正确判据是「我要写的这个目标安全吗」，不是「我这个参数合理吗」**——
   与路径怎么来的无关：默认路径与 `--out` 必须一视同仁。
3. **「冒烟 0 改动」≠「产物内容正确」**：前者是**差分**判据（前后比），
   后者需要**绝对**判据（直接看内容对不对）。凡「跑之前就已错」的文件，差分判据永远发现不了。

> 补充第 4 条（本轮 R3 得出）：**测试写对了，才会把实现对文档的偏离抓出来。**
> `recycle_smoke_tmp.py` 那两个 BUG 都不是「跑一下看看」能发现的 ——
> 尤其第 2 条，它不是「报错了」，而是「**该报的没报**」。
